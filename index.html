General About HTML

What We Need To Write HTML Code

To write HTML code on our computer and view the result in a browser, we need three things:

  • An IDE: the environment where we create folders, files, and write code.
  • A local server: simulates a real server but runs only on our computer so we can see how the website will look when uploaded to the internet.
  • A browser (Firefox, Chrome, etc.): to view the result.

If you have your own preferences for the above, you can use them.

If not, we will suggest what we used for this site:

  • As an IDE, we recommend Visual Studio Code.
  • As a local server, we recommend the Visual Studio Code extension "Live Server" by Ritwick Dey.
  • As a browser, you can use any browser.

If you don’t know how to install them, that’s okay—we’ll explain it now.

Installation And Setup Process

  • On your computer, create a folder anywhere you want where you will store everything related to the website.
    That is, all HTML, CSS, JavaScript files, images, videos, etc.
  • Install VS Code from its official website: https://code.visualstudio.com/
  • Once installed, open it and add the folder you created earlier (there will be an option like "Add folder to workspace" or something similar).
  • Now, you can create folders ("New folder") and files ("New file") inside this folder directly from VS Code.
    For HTML files, the extension must be .html (e.g. example.html)
  • Go to extensions (or press Ctrl + Shift + X) and search for "Live Server" (there may be more than one; we want the one by Ritwick Dey).
    Install it.
  • Once installed, a "Go Live" button will appear at the bottom right.

From now on, by opening the HTML file you want and clicking "Go Live" (or right-clicking anywhere in the file and selecting "Open with Live Server"), your browser will automatically open and display the website.

While Live Server is running, any changes you make to the files will automatically update in the browser as soon as you save them (Ctrl + s).

When you are done, you can stop the Live Server by clicking the same button (which will now show something like "Port: 5500").

Other Extensions

The following extensions are not necessary, but we recommend them as they are quite helpful.

  • Auto Rename Tag by Jun Han
  • Color Highlight by Sergii N
  • HTML CSS Support by ecmel
  • Path Intellisense by Christian Kohler
  • Code Spell Checker by Street Side Software
  • vscode-icons by VSCode Icons Team

Some are for HTML, some for CSS, and some for VS Code in general.

You can install them if you want.

Important: Website Structure

As we have said, each page of the website is an HTML file.

This file can either be in the root of our website folder (the one we added to VS Code), or inside another folder within it.

For example, if the folder we created is called website, its structure could be as follows:

website {
file1.html
folder1 {file2.html}
folder2 {file3.html , folder3 {file4.html}}
}

The location of each HTML file affects the URL of its page when we upload the website to the internet.

For example, if the above files were our website and we uploaded it using the domain name example.com , then the URLs would be:

For "file1.html": https://example.com/file1.html
For "file2.html": https://example.com/folder1/file2.html
For "file3.html": https://example.com/folder2/file3.html
For "file4.html": https://example.com/folder2/folder3/file4.html

In other words, our domain name acts as the equivalent of the website folder on our computer, and to visit each page, we specify step by step where the corresponding HTML file is located.

  • If it is not inside a folder, we write only its name.
  • If it is inside a folder, we write the folder name first and then the file name.
  • The same applies for multiple folders.

However, you may have noticed that almost no URLs end with .html

This happens because there is a special filename for HTML files: index.html, which acts as the default for the folder it is in.

That is, if a folder contains an index.html and no specific HTML file is requested in the URL, the index.html will be used automatically.

So, we could rename our files like this:

website {
index.html
folder1 {index.html}
folder2 {index.html , folder3 {index.html}}
}

This way, the URLs would become:

For the root index.html (home page): https://example.com/
For index.html in folder1: https://example.com/folder1/
For index.html in folder2: https://example.com/folder2/
For index.html in folder3: https://example.com/folder2/folder3/

In this way, we can make URLs cleaner by placing each HTML file in its own folder and naming each file index.html.

We will revisit this topic when we learn how to add links to a page.

HTML Tags

In programming languages, we use "commands".

In HTML (which is not a programming language), we use HTML tags (or simply tags).

There are two types of tags: paired tags and self-closing tags.

Paired tags have the form:

<example> ... </example>

or:

<example>
...
</example>

Self-closing tags have the form:

<example ... >

If we place some tags inside others, IDEs usually automatically add two or four spaces to the inner tags to make the code more "clean".

That is:

<example1>
  <example2>
  ...
  </example2>
</example1>

If you like, you can keep this formatting, but you should keep in mind that spaces are included in the file size, which can be important if you plan to upload the site using a free hosting service.

More about this topic on the page "How to Upload a Static Website to the Internet".

We did not keep them.

Basic HTML File Structure

There are some tags that must exist in every HTML file.

These essentially form the structure of the file, which is the following:

<!Doctype html>
<html>
  <head>
  ...
  </head>
  <body>
  ...
  </body>
</html>

The <!Doctype html> goes at the top of the file and tells browsers that the file is an HTML document.

The <html> ... </html> tags define the beginning and end of the code.

Inside them, it is recommended to also declare the language of the page content by writing:

  • <html lang="en"> for English.
  • <html lang="el"> for Greek.
  • Similarly, use the appropriate two-letter code for any language.

Inside the html tags, we divide the code into two parts, the head and the body, using the corresponding tags.

Before explaining what we can write in the head and in the body, we will first mention what comments are.

Comments

They are ignored by browsers, so anything written inside them will not appear on the page.

They are useful for writing notes about the code or temporarily removing something without deleting it, by turning it into a comment.

A comment is anything written between the symbols <!-- -->

For example:

<!-- This
is a
comment.  
-->

Head

There are many HTML tags that can be used inside the head of a file, but we cannot cover all of them.

Below we present the most important ones, grouped into categories.

Essential Tags

1) <meta charset="UTF-8">
2) <title> <!--the page title goes here--> </title>
3) <meta name="description" content="a short description of the page goes here">
4) <meta name="author" content="FirstName LastName">
5) <meta name="viewport" content="width=device-width, initial-scale=1.0">
6) <meta property="og:site_name" content="the site name goes here">
  • The 1st defines which characters are used in the file. UTF-8 includes all letters of every language, numbers, special characters, etc., so you don’t need to change it.
  • The 2nd defines the page title. It appears on the browser tab and in search results. It should be descriptive (but up to 50–60 characters) and unique for each page.
  • The 3rd is used to provide a short description (about 150 characters) of the page, which appears below the title in search results. If it is missing, Google tries to generate one automatically.
  • The 4th defines who created the page. Simply write your name.
  • The 5th is necessary for proper display on mobile devices and tablets. Without it, the page may appear zoomed or distorted.
  • The 6th defines the site name (e.g. FreeMath13). It appears in search results and on social media when someone shares a page from your site.

Tags For Connecting CSS And JavaScript Files

We will cover these tags in more detail in their respective courses. For now, we will just see how they are written.

1) <script src="path to JavaScript file" defer></script>
2) <link rel="stylesheet" href="path to CSS file">
3) <style> <!--CSS rules--> </style>

With the 1st, the JavaScript code inside the specified file will be executed.

With the 2nd, the CSS rules from the specified file will be applied.

We will see how to write paths when we learn how to add links to a page.

The 3rd is used to write CSS rules directly inside the page instead of in a CSS file.

Creating A Site Logo

The logo of a website is called a favicon, and it is the small image that appears on the browser tab, in search results, and when someone bookmarks a page.

There are various websites to create a favicon. A free one is https://favicon.io

There, you follow the instructions, and once finished you will need to download some .png , .ico and .webmanifest files (these are the favicon in different sizes), which should be placed in the root of your website folder (not inside other folders).

You will also need to copy some lines of code they provide and paste them into the head of every page so that each page loads the favicon.

The code will look something like this:

<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png">
<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32x32.png">
<link rel="icon" type="image/png" sizes="16x16" href="/favicon-16x16.png">
<link rel="manifest" href="/site.webmanifest">

Tags For Multilingual Sites

If a page has the same content as another and the only difference is the language, search engines may not correctly associate each version with the appropriate audience.

As a result, they might show the wrong version in a country (e.g. the English version in Greece) or choose one version to display in search results while ignoring the others.

To help search engines understand the relationship between these pages, you can add the following in the head of each page:

<link rel="alternate" hreflang="language code like en, el, es, etc." href="URL of the corresponding page">
<link rel="alternate" hreflang="language code like en, el, es, etc." href="URL of the corresponding page">
<!--as many of the above tags as needed: one for each language-->
<link rel="canonical" href="URL of the current page">
<link rel="alternate" hreflang="x-default" href="URL of the default page">

Note that the URLs must be the actual URLs (https://...), so you need to have purchased your domain name to complete these tags.

For example, suppose the site domain is example.com and it consists of one page written in English, which is also translated into Greek.

That is, the site contains an index.html (English version, which is the default) and a gr folder with another index.html (Greek version).

Then, in the HTML file of the English page, we would write:

<link rel="alternate" hreflang="en" href="https://example.com/">
<link rel="alternate" hreflang="el" href="https://example.com/gr/">
<link rel="canonical" href="https://example.com/">
<link rel="alternate" hreflang="x-default" href="https://example.com/">

While in the HTML file of the Greek page:

<link rel="alternate" hreflang="en" href="https://example.com/">
<link rel="alternate" hreflang="el" href="https://example.com/gr/">
<link rel="canonical" href="https://example.com/gr/">
<link rel="alternate" hreflang="x-default" href="https://example.com/">

Essentially, only the tag with rel="canonical" changes, since it points to the URL of the page where the tag is placed.

Body

Before we start looking at how the content of a page is created, there is one last thing: the structure of the body.

Body Structure

The following tags are not technically required, but in practice they are.

Specifically, it is recommended to divide the body into three parts:

<body>
<header>
...
</header>
<main>
...
</main>
<footer>
...
</footer>
</body>

The header is the introduction of the page: title, contents as anchor links (we will see what these are shortly), a short paragraph, etc.

The main contains all the main content.

The footer is the closing part of the page: links to other pages, contact information, the phrase © SiteName. All rights reserved, etc.

Headings

To write a heading, we use one of the following tags:

<h1> ... </h1>
<h2> ... </h2>
<h3> ... </h3>
<h4> ... </h4>
<h5> ... </h5>
<h6> ... </h6>

For example: <h1>How to Upload a Static Website to the Internet</h1>

The difference between them is their size and their intended use.

In terms of size, <h1> has the largest size.

<h2> is slightly smaller, <h3> even smaller, and so on, down to <h6>, which is the smallest.

Regarding their usage, it is recommended to follow this structure:

  • The main title of the page (the one at the top) should be in <h1>
  • If the page is divided into sections (which it likely is), their titles should be in <h2>
  • If a section is divided into subsections, their titles should be in <h3>
  • If a subsection is further divided, their titles should be in <h4>
  • Similarly for <h5> and <h6>

This is not mandatory, but it is very important for search engines to better understand the page (and therefore increase the chances of appearing in search results).

If you do not like the default heading sizes, that is not a problem, as they can be changed using CSS, as we will show in the corresponding course.

Text

To write a paragraph, we use the <p> ... </p> tags.

We simply write the text we want between them.

If you want to change line at some point, you must either use the <br> tag at that point, or close the paragraph and create a new one with new <p> tags.

Simply pressing Enter in your file is not enough.

Text Details

The following tags should be used only inside other tags.

  • For bold text: <b> ... </b>
  • For underlined text: <u> ... </u>
  • For italic text: <i> ... </i>
  • For strikethrough text: <s> ... </s>
  • For superscript (slightly above): <sup> ... </sup>
  • For subscript (slightly below): <sub> ... </sub>

To draw a horizontal line between paragraphs, write <hr> between them (outside the <p> tags).

Links

There are three types of links:

  • Links that take us to another page of our website.
  • Links that take us to another website.
  • Links that take us to a different position on the same page (anchor links).

In all cases, we use the tag <a href="..."> ... </a>

In href="..." we write the location we want to navigate to when the link is clicked.

Inside ... we write the element that, when clicked, will take us to that location.

This can be text, an image, or anything else, except <button> tags, which we will see later.

How To Write The Location In href

  • If we want to create a link to another website, we simply write its URL.
    That is: href="https://example.com/"
  • If we want to create a link to a page of our own website, we replace the part https://our-domain-name/ with a slash /
    Then, the same rules we described earlier about structure apply:
    • If an HTML file is not inside a folder, we write only its name (or nothing if it is called index.html).
    • If it is inside a folder, we write the folder name first and then the file name (or nothing if it is called index.html).
    • Similarly for multiple folders, we write all folder names in order and then the file name (or nothing if it is called index.html).

For example, suppose our website consists of the following files:

index.html
style.css
colors.js
linear-algebra-I {index.html , gr {index.html}}
linear-algebra-II {index.html , gr {index.html}}

This is a small website with two Linear Algebra courses.

  • index.html is the homepage.
  • style.css and colors.js are related to their respective languages and are not relevant in this course.
  • There is a folder called linear-algebra-I containing an index.html (English version) and a gr folder containing another index.html (Greek version).
  • There is also a folder called linear-algebra-II with the same structure for the second course.

Let’s see what we would write in href="..." to create links for each page:

  • Homepage: "/"
  • Linear Algebra I (English): "/linear-algebra-I/"
  • Linear Algebra I (Greek): "/linear-algebra-I/gr/"
  • Linear Algebra II (English): "/linear-algebra-II/"
  • Linear Algebra II (Greek): "/linear-algebra-II/gr/"
  • For style.css and colors.js, as mentioned earlier, we use similar paths in the head tags:
    "/style.css" and "/colors.js"

We could also include index.html at the end, but it makes no difference, so there is no reason to do so.

Finally, note that links open in the same browser tab by default.

To open them in a new tab, add target="_blank" like this:

<a href="..." target="_blank">...</a>

IDs And Anchor Links

To create anchor links (links that move us up or down within the same page), we first need to understand what ids are.

By giving a tag an id, we can distinguish it from all other tags with the same name.

This is especially useful in CSS and JavaScript, but it is also how we create anchor links.

An id is assigned by writing inside a tag:

id="word-or-phrase-without-spaces"

For example:

<h2 id="part13">...</h2>

To create an anchor link:

  • We assign an id to the tag containing the content we want to navigate to.
  • In the link’s href, we write "#the-id-we-used"
  • If we simply write "#", the link takes us to the top of the page.

For example:

...
<h3 id="definition-of-linear-transformations">Definition of Linear Transformations<h3>
...
<p>If you don’t remember the definition of linear transformations mentioned earlier, see it <a href="#definition-of-linear-transformations">here</a>.</p>

Clicking "here" will take us to that section of the page, where the heading will appear at the top.

nav tags

Finally, when we have a list, a table, or generally many links together, it is recommended to wrap them inside <nav> ... </nav>

These indicate that the specific area contains navigation links and help search engines, screen readers, etc., better understand the page.

They should only be used in sections with many links, not for every individual link.

Images And Videos

To add an image, we use the tag: <img src="..." alt="...">

In src="..." we write the location of the image using the same logic as before for file paths.

This is because the image we want to add to the page is also a file, such as .jpg, .jpeg, .png, or something else.

Of course, we can also use a link to an image from the internet, but if we plan to publish the site, this is uncommon due to copyright issues.

In alt="..." we write a short description of the image. This helps with website accessibility.

Finally, if we don’t like the dimensions of the image, we can change them by adding width="..." and height="..." somewhere inside the tag.

There are many ways to define width and height. The most common are pixels (e.g. width="100px") and percentage of the screen (e.g. width="40%").

For example, suppose we have an image graphs.png that contains graphs of some functions and is stored inside a folder called images in our site.

To add it to the page with square dimensions of 300 pixels, we would write:

<img src="/images/graphs.png" alt="Graphs of functions" width="300px" height="300px">

However, if its original shape is not square, it may not display correctly.

For this reason, we usually define only one dimension, and the other is set automatically to preserve the original aspect ratio.

Videos

To add a video, we use the tags:

<video src="..." controls>...</video>

In src="..." we write the location of the video using the same logic as before for file paths.

In ... we write what we want to appear if, for some reason, the video cannot load (e.g. loading failure).

The controls attribute allows us to play, pause, go fullscreen, etc.

Without it, the video will essentially do nothing—it will just exist.

We can also add any of the following (just leave a space after controls and write them):

  • poster="image location": adds a thumbnail to the video, meaning that before it starts, the specified image will be shown.
  • autoplay: makes the video start automatically.
  • loop: makes the video restart automatically every time it ends.
  • width and height: same use as in images.
Videos from YouTube

If we want to add a video from YouTube:

  • Find it in a browser.
  • Click share.
  • Click embed.
  • Copy and paste the HTML code that appears.

Ordered Lists

To add a list with numbered items, we write:

<ol>
<li>item1</li>
<li>item2</li>
<li>item3</li>
...
</ol>

The items can be anything: text, links, images, etc.

Example
  1. Item 1
  2. Item 2
  3. Item 3

By adding type="symbol" next to ol inside the tag, we change the numbering style.

Specifically:

  • If the symbol is A, it uses A,B,C,D,...
  • If the symbol is a, it uses a,b,c,d,...
  • If the symbol is i, it uses i,ii,iii,iv,...
  • If the symbol is I, it uses I,II,III,IV,...

Tables

To add a table, we write:

<table>
<thead>
  <tr><th scope="col">...</th> <th scope="col">...</th> <th scope="col">...</th> <!--as many <th scope="col">...</th> pairs as we want--> </tr>
</thead>
<tbody>
  <tr><td scope="row">...</td> <td>...</td> <td>...</td> <!--as many <td>...</td> pairs as we want--> </tr>
  <tr><td scope="row">...</td> <td>...</td> <td>...</td> <!--as many <td>...</td> pairs as we want--> </tr>
  <tr><td scope="row">...</td> <td>...</td> <td>...</td> <!--as many <td>...</td> pairs as we want--> </tr>
  <!--as many rows as we want-->
</tbody>
</table>
  • Each pair of <tr> is a row of the table.
  • Each pair of <th> is a column header in the first row.
  • Each pair of <td> is a cell in the remaining rows.
  • That is, inside the ... of <th> and <td> we write the data for that cell.
  • The <thead> tags define the first row (column titles).
  • The <tbody> tags define the rest of the rows (data).
  • The scope="col" defines columns in the first row.
  • The scope="row" defines rows in the first column (except the first row).

The <thead> and <tbody>, as well as scope="col" and scope="row", are not required.

However, they help search engines, screen readers, etc., understand the table better, so it is good practice to include them.

Finally, to control size, appearance, borders, etc., we need CSS, which we will cover in the corresponding course.

Buttons

To add a button, we use the tag: <button>word or phrase</button>

Buttons are only useful when combined with JavaScript to perform actions. Otherwise, they are essentially useless.

For example, the buttons at the top of the page are connected to JavaScript and change the page theme.

However, the following is not connected to JavaScript, so it does nothing.

Also, as shown, CSS is needed to improve their appearance.

Iframes

Iframes are a way to embed another webpage inside our own.

That is, if we write the following, we will see the selected webpage inside a frame on our page, and it will function normally as if we were browsing it directly.

However, some websites do not allow this for security reasons.

<iframe src="URL-of-the-webpage">...</iframe>

In src we write the URL of the webpage, and in ... we write what should appear if the page cannot load or does not allow embedding.

We can also define width and height as we did for images and videos.

Containers

The <span>...</span> and <div>...</div> tags do not have a specific function.

They act only as containers, meaning they are used to contain other tags.

Their importance will become clear when we study CSS.

In short, we can use a container to create a menu with links by placing as many <a> tags as we want inside a <div>, and giving the menu a different background color so it stands out from the page.

In fact, the menu can appear only when we click a <button> and disappear when we click elsewhere (using JavaScript).

This is just one example; in reality, there are many uses for these tags.

Finally, note that <div> tags are block elements, while <span> tags are inline elements.

  • Block elements take up the entire line for their content, even if they do not need it. An example of a block element is a heading.
  • Inline elements take up only as much space as their content requires (allowing other inline elements next to them). An example of an inline element is an image.

Code, Pre & Math Tags

code tags

Used when we want to write code inside the page (e.g. for programming-related websites).

Usage: <code>...</code>

pre tags

Used when we want the content to appear exactly as it is written in the HTML file, with the same spacing and line breaks.

For example, if we leave spaces at the beginning of each line, they will also appear on the screen.

They are also useful when writing code across multiple lines.

Usage:

<pre>
...
</pre>

math tags

Used when we want to write mathematical expressions.

Usage: <math>...</math>

However, if the page is purely mathematical, then to display properly formatted math symbols, we usually use JavaScript libraries such as MathJax, KaTeX, or others.

If you are interested, you can visit the page "MathJax Commands", where we explain how to use MathJax on a page and list commands for various mathematical symbols such as fractions, roots, integrals, matrices, and many more.

Special Characters

There are some characters that have a specific function in HTML and therefore should not be included in the text of a page.

For example, the symbols < and > are used in tags, therefore if we use them inside text, there is a chance that a problem may occur.

That is, in the paragraph <p> 1<2 </p> we want to use the symbol < as "less than", but in reality this will be interpreted as the start of a tag, which may cause a problem on the page.

For this reason, HTML provides some codes that replace these characters.

The most important are:

  • &lt; for <
  • &gt; for >
  • &amp; for &

Also, there are codes for characters without a special function.

These are used for convenience, since it's easier to write a code than to search online to find the character we want and copy and paste it.

For example:

  • For © we write &copy;
  • For ® we write &reg;
  • For ™ we write &trade;
  • For • we write &bull;
  • For £ we write &pound;
  • For € we write &euro;
  • For ¥ we write &yen;
  • For ↑ we write &uarr;
  • For ← we write &larr;
  • For ↓ we write &darr;
  • For → we write &rarr;
  • etc.
